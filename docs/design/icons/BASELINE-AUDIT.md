## 3. 需要在正式基线前处理的问题

### 3.1 播放三角：旧总偏移不能成为标准答案

原参考参数中，play的总平移为 `-1.943u`（x轴）；本次重栅格化后alpha墨量重心约为 `(10.330, 12.000)u`。这不是感知中心的测量，也不能证明字形一定偏移多少，但足以说明“平移后就已经严格居中”没有充分证据。

建议重新建立三角母版，分开源稿归一化与微调，对照未微调、邻近候选、Pause及固定按钮。不得把1.670u反向平移直接当作修复，因为墨量重心仍不是唯一判断。

### 3.2 三枚草案触及新留白门槛

以CairoSVG将每枚渲染为960×960，alpha阈值128确定近似可见范围，换算为24u坐标。与拟定的可见范围 `[1.5,22.5]` 比较，以下三枚触发复审。这个阈值是新增项目提案，**并非这些草案违反了当时不存在的规则**。

| 草案 | 本次近似可见边界[xmin,ymin,xmax,ymax]，u | 需要处理 |
| --- | --- | --- |
| branch | 3.550, 1.850, 21.300, 22.600 | 下侧范围；优先调整节点母体与总平移 |
| download | 2.625, 1.275, 21.375, 21.025 | 上侧留白；需与Upload统一审查 |
| network | 0.825, 0.825, 23.175, 23.175 | 四周均过近；考虑节点收拢或更克制主体 |

以上bbox带有采样与抗锯齿误差，不是精确解析几何边界。其他33枚没有触发这一特定阈值，**不等于其他33枚已通过视觉验收**。

### 3.3 上传／下载：单枚补偿不能破坏共同托盘

参考稿download与upload的y轴总平移分别是 `-0.861u` 和 `-0.519u`。它们应在同一容器中对照托盘基线与切换效果；需要保持的共享结构不应被各自的墨量算法推到不同位置。

### 3.4 复杂仪器：16px与14px尚未获得真实产品证据

OpticalCore、Microscope、Satellite、Caliper、Network等需要重点核对结构密度、线间净空和识别性。不能仅因为256px透明PNG或参考板放大图清晰，就写支持14px。必要时删去内部细节、限定最小尺寸或提供批准的简化稿。

### 3.5 公共名称与语义不能机械转换

参考包record表达文件，而非录制；close可映射现有X；settings与check对应已有同名语义。FolderOpen与关闭文件夹、MessagesSquare与单一气泡不等价。已有名称如果更换视觉，仍需前后对照，不是“名称不变所以无影响”。

## 5. 审查顺序

先建立12枚基准候选的真实证据，再扩展其余图形。play与边界触发项优先处理；与已有Settings／Check／X有关的视觉变更先做源码与参考稿对照；新命名与现有语义存在重叠时先解决命名，不先新增一批导出再清理。

不要为使本表全部“通过”而同步放宽主规范；当主规范确实不合理时，应单独记录设计决策、代表性对照与适用范围。
