# 图标设计与开发验收清单

版本：1.0 提案版｜依据：[ICONS.md](../ICONS.md)｜日期：2026-10-14

本清单供新增、重绘、替换、状态变更和包装器变更使用。未采用主规范之前，它是拟定门槛；采用后作为图标PR的验收附件。**复选框默认未通过，不代表检查已执行。**

## 1. 变更范围记录

| 字段 | 填写要求 |
| --- | --- |
| 任务与提交 | PR、分支、commit、受影响文件；仅填写真实存在的对象 |
| 变更类型 | 新增字形／几何调整／语义调整／包装器／布局／迁移／规范变更 |
| 图标名称 | 区分正式IconName、候选名和参考稿文件名 |
| 使用场景 | 具体按钮、列表、导航、工具栏或独立状态图形 |
| 支持尺寸 | 列出实际承诺的14／16／18／20／24px，不能直接写“全尺寸” |
| 环境 | 操作系统、浏览器或WebView版本、DPR、OS缩放、浏览器缩放 |
| 规范版本 | specVersion、字形designRevision、对照基准版本 |
| 当前状态 | draft／candidate／approved／deprecated；发布版本另记 |

## 2. 阻断级别与放行规则

**P0：必须先修复。** 语义误导、禁用仍可执行、缺少必要名称、非法SVG内容、未经批准改变家族核心规则、明显裁切或严重失去识别性、无证据声明通过。

**P1：进入正式基线前必须闭环。** 明显光学偏移、同族重量／结构不一致、声明支持的尺寸未验证、目标平台证据缺失、状态切换跳位、未核实来源、草案与实现不一致。

**P2：可在记录后安排改进。** 不影响语义与必要尺寸的维护性或文档改进。不能把核心风格问题降级为P2，也不能用综合评分抵消P0／P1。

未完成的必要条件记录为 `blocked`；不适用项记录 `N/A + 理由`。无需修改的字形保留其既有证据，但触及相应能力的变更必须重新验证。

## 3. 语义与复用

- [ ] SEM-01 用一句话准确描述图标对象／操作，并写出至少一个禁止误用场景。
- [ ] SEM-02 检查公共IconName与已有消费者，没有重复创建同义图标。
- [ ] SEM-03 名称遵循PascalCase；源文件遵循kebab-case；不存在颜色、尺寸、业务页面名或无解释数字后缀。
- [ ] SEM-04 用户能区分容易混淆的对象，如Folder／FolderOpen、文档／录制、上传／导入、关闭／删除。
- [ ] SEM-05 缺失图标没有用不相关图形或静默空白掩盖。
- [ ] SEM-06 状态、方向、对象类型不依赖仅有的颜色差异。

证据：单枚规格、公共集合检索结果、语义对照及使用场景。

## 4. 风格与几何

- [ ] GEO-01 viewBox为0 0 24 24；没有通过改viewBox遮掩缩放或对齐问题。
- [ ] GEO-02 默认1.75u描边、round cap／join、单色currentColor；未按图标或主题私自覆盖。
- [ ] GEO-03 透明字形，不带背景板、文字、编号、十字辅助线或无语义的橙色标记。
- [ ] GEO-04 需要对称的中轴、支架、刻度、括角、圆心和重复结构实际对齐。
- [ ] GEO-05 同族页签、折页、切角、把手和内部线段采用共同尺度。
- [ ] GEO-06 含描边的可见边界符合主规范留白；例外有明确批准记录。
- [ ] GEO-07 必须分开的笔画具有足够净间隙；无意相切、粘连、端点短刺已处理。
- [ ] GEO-08 空心节点没有用背景色遮挡底线；暗色下不出现白块或穿线。
- [ ] GEO-09 删除不必要的微小装饰；复杂科研图标没有变成仪器插画。
- [ ] GEO-10 与已批准的稀疏／密集／圆／方基准混排后重量协调，而非只把所有图形撑到同样大。

证据：规范化SVG、含描边边界记录、同族对照、放大结构图。程序测量不能替代GEO-09／10的人工判断。

## 5. 光学居中与成组稳定

- [ ] OPT-01 图标槽位与实际布局正确居中，SVG不被flex压缩。
- [ ] OPT-02 区分几何归一化和光学微调，并分别记录；没有直接复制旧稿总translation。
- [ ] OPT-03 非对称图标比较零微调与邻近候选，而不是套用统一方向经验值。
- [ ] OPT-04 微调超过0.5u触发复审；超过1u先解释并优先重构几何，未把原稿总平移误判成微调。
- [ ] OPT-05 SVG内部或库内只应用一次校准；消费端无按名称散落的margin／top／translate补丁。
- [ ] OPT-06 去掉辅助线，在16／20／24px原尺寸观察仍没有明显偏移。
- [ ] OPT-07 同一字形在按钮、列表和导航中位置稳定；局部组件问题没有被错误修到字形里。
- [ ] OPT-08 播放／暂停、上传／下载、展开／收起等相关图标切换时主体或共用基线不跳位。
- [ ] OPT-09 对齐结论包含人工复核说明，而不是只报告bbox、墨量重心或算法分数。

证据：统一槽位中的候选比较、最终版本、原尺寸图、成对切换录屏或真实连续截图、审批记录。

## 6. 尺寸、主题与交互场景

- [ ] RND-01 新增／重绘字形已覆盖16／20／24px浅色与深色；支持限制在元数据和实际使用中一致。
- [ ] RND-02 实际用到的14／18px单独检查；未擅自修改公共icon-size token。
- [ ] RND-03 未默认添加non-scaling-stroke、crispEdges、缩放补丁或深色专属加粗。
- [ ] RND-04 基础截图覆盖DPR1／DPR2；记录截图是否被二次缩放。
- [ ] RND-05 必要的Windows与macOS抽样来自真实平台；模拟和Linux结果明确标注。
- [ ] RND-06 相同浏览器／系统／DPR内比较前后差异，不要求跨环境抗锯齿逐像素一致。
- [ ] RND-07 有实际受影响组件的真实运行截图；静态参考板没有冒充运行证据。
- [ ] RND-08 存在布局变更时按项目要求覆盖320／390／768／1280／1920视口；没有图标压缩、裁切或对齐漂移。
- [ ] RND-09 颜色来自正确token角色，没有硬编码色值或白色遮挡。
- [ ] RND-10 default／hover／pressed／selected／focus-visible／disabled／loading等适用状态完整，固定槽位不跳动。

证据：测试环境表、尺寸主题矩阵、真实组件截图、适用状态说明。

## 7. 可访问性与方向

- [ ] A11Y-01 图标重复可见文字时隐藏，避免重复朗读；独立传意时有正确名称。
- [ ] A11Y-02 图标按钮使用真实button／link及可访问名称，不把SVG自身做成不完整控件。
- [ ] A11Y-03 核对当前包装器的aria-label分支；没有误以为只传aria-labelledby就已得到正确行为。
- [ ] A11Y-04 必要图形的实际前景／背景组合通过非文本对比度要求，同时检查细线原尺寸可读性。
- [ ] A11Y-05 点击目标与可见图形分开评估；没有把44px误写成WCAG 2.2 AA的统一最低值。
- [ ] A11Y-06 焦点可见且与selected状态可区分；disabled语义和行为都正确。
- [ ] A11Y-07 记录物理方向／逻辑阅读方向／非方向对象；RTL没有无差别镜像。
- [ ] A11Y-08 状态动效使用项目机制；减少动态效果时仍可理解状态。
- [ ] A11Y-09 键盘与必要的屏幕阅读器检查有实际记录；仅静态扫描通过未被当成完整验收。

证据：DOM／可访问树、自动测试结果、键盘与辅助技术记录、对比度计算、目标尺寸与间距测量。

## 8. SVG与工程实现

- [ ] ENG-01 无script、事件属性、外部URL、foreignObject、嵌入图片／字体或其他未授权SVG能力。
- [ ] ENG-02 无不必要重复路径、隐藏对象、冲突ID或导出噪声；优化前后视觉一致。
- [ ] ENG-03 新图标通过现有公共入口；未新增平行图库、临时字体图标或外部运行时图标依赖。
- [ ] ENG-04 IconName、registry、导出、文档和展示列表保持一致；缺图有明确处理。
- [ ] ENG-05 设计源与React几何的同步方向明确，没有两份独立正式源。
- [ ] ENG-06 没有删除或悄然改变已有公共属性、名称、token；需要变更时附ADR和迁移说明。
- [ ] ENG-07 原AgentIcon／内联图标的迁移按组件处理，没有机械改viewBox了事。
- [ ] ENG-08 运行了本次影响范围内的类型、单元、构建与必要的视觉测试，并保存命令、退出码和结果摘要。
- [ ] ENG-09 包装器或导出变更通过真实消费／打包验证，没有无测量地承诺逐图标tree-shaking。

现有React包已核实的脚本可通过以下方式调用；这里是执行入口示意，**本次文档交付没有运行它们**：

```sh
pnpm --filter @wzrhine/react typecheck
pnpm --filter @wzrhine/react test
pnpm --filter @wzrhine/react build
```

新增图标专用lint、截图或元数据检查命令前，先实现并验证脚本，再写入README；不得引用不存在的 `pnpm icons:check` 之类命令。

## 10. 证据目录建议

建议按真实提交或任务记录组织，目录名中的字段由实际信息填写：

```text
icon-review/<实际任务ID>/
  scope.md                    变更范围与适用项
  environment.md              环境及限制
  geometry/                   边界与源文件差异
  optical/                    未微调、候选与最终版本
  sizes-themes/               尺寸与主题对照
  contexts/                   真实组件落位
  checks/                     命令、退出码、输出摘要
  decision.md                 维护者决定与剩余问题
```

避免重复拷贝巨大截图；证据可引用已存在的CI产物或存储路径，但必须可访问、可定位到本次提交。不得写一个不可访问链接就视作证据齐全。
