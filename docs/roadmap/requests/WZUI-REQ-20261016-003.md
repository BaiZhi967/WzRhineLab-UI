## 2. 真实场景

- 用户目的：用 WzRhineLab-UI 公开组件快速搭建类似 Obsidian/Typora 的 Markdown 工作台。
- 期望路径：打开工作区 → 从文件树选择文档 → 在标签中切换 → 编辑或预览 → 查看目录 → 保存/处理错误。
- 当前替代：调用方自行拼接 `Workbench`、`Tree`、`Tabs`、`SectionIndex` 和自定义编辑器，布局和状态容易分叉。
- 影响范围：Showcase、未来参考应用和需要 Markdown 读写的页面。

## 3. 归属判断

- 类型：recipe / 页面组合
- 目标目录：`apps/docs` 参考场景或独立 recipes 文档；是否建包待架构评估
- 现有公共 API：工作台外壳大部分可以复用；新能力来自内容层和编辑器层。
- 必须进入 recipe：文件树、文档标签、编辑/预览双栏、目录、保存状态和窄屏降级的组合说明。
- 留在宿主：文件列表数据、打开/关闭文档、持久化、自动保存、路由和业务操作。
- 不建议：为单一工作台新增第二个全局外壳或把布局组合全部提升为公共组件。

## 5. API 和依赖

- Recipe 只使用公开包入口和文档化 slots，不导入源码路径。
- 推荐组合：`Workbench`、`Tree`、`Tabs`、`ResizeHandle`、`SectionIndex`、`CommandPalette`、`AlertDialog`、候选 `@wzrhine/content` 与 `@wzrhine/editor`。
- 文件树节点、文档标签和目录项使用稳定 ID。
- Recipe 不新增网络、文件系统、查询缓存和权限依赖。
- 可在 Showcase 中使用静态 fixture，必须明确标注为示例数据。

## 6. 交互、无障碍和动效

- 文件树沿用现有 tree 键盘路径；标签沿用 tabs 语义；目录沿用 `SectionIndex` 合同。
- 文档关闭、侧栏折叠和 Drawer 关闭都要有明确焦点回收。
- 保存、加载、错误和冲突状态用文本和语义标记表达，不依赖装饰动画。
- 仅在面板进入/退出时使用可中断的轻量 motion；reduced-motion 使用静态切换。
- recipe 记录窄屏、长标题、长路径、双实例和容器嵌入行为。
