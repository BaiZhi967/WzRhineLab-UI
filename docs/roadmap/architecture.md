# WzUI 前端平台架构与能力边界

> 2026-10-14；基线 0.2.0。现有五包是实现事实；本文中的 patterns、内容、图表、编辑器和应用支持模块均为规划。范围与顺序见 [总路线](README.md)。

## 1. 架构目标

让公共能力统一维护、业务仍能独立演进。组件能单独使用，页面模式能组合，重依赖能选装；维护者能够理解每个模块做什么、如何使用、依赖什么，以及从哪里验证。

不建立“所有 React 代码都必须进入一个万能包”的规则。长期复用同一交互、视觉或前端领域能力，就可以进入平台；深度绑定某个宿主的网络、数据库、原生权限和运行时仍留在宿主。

## 2. 现有基础与依赖规则

现有包为 `@wzrhine/tokens`、`@wzrhine/react`、`@wzrhine/effects`、`@wzrhine/agent-core` 和 `@wzrhine/agent`。继续使用 React 19、Base UI 单一交互底座、语义 HTML、`motion/react` 和 `--rl-*` tokens；依赖升级单独记录，不以规划中的版本号冒充已验证兼容范围。

当前开发参考 Motion 14.1.0；包 peer 范围与锁文件的实测版本不是同一概念。本轮路线不改动它们。

依赖必须单向：tokens 提供基础；React 提供通用行为和呈现；页面／领域层消费基础；示例消费公开接口。基础组件不反向依赖页面、智能体、编辑器或图表层。

## 3. 目标分层与候选包

| 模块 | 责任 | 依赖与排除 |
| --- | --- | --- |
| tokens | 语义变量、主题基础、契约清单 | 不依赖 React 或产品数据 |
| react | 通用交互、原语与已发布档案组件 | 不引入重型编辑、图表、文件系统依赖 |
| patterns（拟议） | ListDetail、集合工具区、详情组合等稳定公共模式 | 依赖 react／tokens；不依赖 agent |
| 现有领域 UI | view-model、领域状态呈现与 actions | 不执行真实权限、请求或运行时命令 |
| 内容／分析／编辑适配（候选） | 对成熟引擎做主题和交互接入 | 独立安装或明确可选依赖；懒加载与 fallback |
| recipes／starters | 可改写的页面和应用起点 | 使用公共入口，不复制基础实现 |

0.3.0 在 P030-00 决定是否建立 `@wzrhine/patterns`。只有存在稳定交互合同、独立消费价值与实际公共组件时才拆包。只有布局拼接时先交付 recipes，不为占位创建空包。

候选目录如下，均须在实现任务中实际创建与验证：

```text
packages/patterns/             # 若 P030-00 决策通过
  src/layout/                 # 主从与检查面板
  src/collection/             # 工具区、筛选、选择、视图
  src/record/                 # 记录详情与章节
  src/index.ts
  src/styles.css
examples/archive-desk/         # 扩展现有参考应用
  ...                         # 具体内部目录由实施设计确定
```

## 4. 组件、模式、recipe 与业务的判定

**基础组件**拥有独立语义和稳定行为，例如输入框和弹层。**模式组件**拥有跨页面复用的交互合同，例如关闭详情后的焦点返回、查询状态呈现和选择操作区。**Recipe**展示如何组合组件构成页面，不负责扩大公共 API。**业务模块**连接真实接口和业务规则，留在消费项目。

新建公共组件前必须说明：可复用的行为是什么、现有能力为何不足、调用者需要控制什么、失败和取消如何表现、为什么不是一个 recipe。仅增加 padding、标题与背景，不足以证明需要公共组件。

不要求两个外部项目才能抽象。一个清楚的场景加一组不同数据形态的库内验证，也可以证明边界。反过来，“可能人人都需要”不能代替真实使用目的。

## 5. 状态与数据所有权

| 状态 | 默认所有者 | 公共层的职责 |
| --- | --- | --- |
| 搜索词、筛选、排序、页码 | 调用者 | 受控值与变更事件；不擅自请求 |
| selectedIds、当前详情 ID、视图模式 | 调用者 | 稳定 ID 合同、可见状态与动作 |
| hover、局部展开、焦点记录 | 组件 | 不越过公开可控边界 |
| loading、error、执行结果 | 调用者 | 忠实呈现，不推断成功 |
| 数据缓存、取消请求、去重、过期策略 | 宿主或参考应用 adapter | 公共层不绑定 Query／Store |
| UI 偏好持久化 | 可注入适配或宿主 | 命名空间、版本、失败降级 |
| 用户权限、凭据、文件读取授权 | 宿主 | 不把按钮 disabled 当安全机制 |

受控组件不能在回调后假定父级已经接受变化。暴露 default 值的非受控模式必须有清楚的使用理由，不能让同一个字段同时由内外两个状态源写入。

## 6. 集合浏览合同

集合条目通过 `getItemId` 或等价方式提供稳定 ID，不能使用下标。查询、排序与分页由调用者执行，组件不按照自己猜测的字段类型变换数据。

0.3.0 的选择基于已明确的有限 ID 集合。视图切换保持选择；分页范围、可见范围与全部结果范围分别说明。首版不提供服务端“全部筛选结果已选中”的隐式令牌协议。

单击打开与选中使用可区分的操作入口；多选使用有名称的 checkbox。资源卡片不通过 `div onClick` 模拟按钮，也不把内嵌操作放入整个可点击按钮内部。无复杂网格导航需求时使用列表语义，不虚构 ARIA grid。

过滤后的隐藏选择不得静默丢失；界面显示总选择及当前范围，清除策略由调用者决定。真实删除后的 ID 失效由 adapter 清理并通知，库组件不猜测异步业务结果。

## 7. 布局、滚动与焦点合同

Workbench 继续负责应用外壳。ListDetail 是可嵌入的主从模式，不再渲染第二个应用级导航或重复 `main` landmark。

宽布局采用可见的列表与详情；窄布局使用替换式详情并提供返回入口。InspectorPanel 是语义检查区域，只有调用者明确选择覆盖层时才组合 Drawer／Dialog；不得偷偷增加第二套焦点陷阱。

每一滚动区域要声明所有者。页面宽度变化不能导致双滚动条、焦点被隐藏或列表位置被无理由重置。SectionIndex 需要显式滚动根；无 JS 时仍能通过锚点定位，减动模式不进行平滑位移。

关闭详情优先返回打开它的控件；控件已不存在时转到稳定列表标题或工具区。重新打开与快速切换取消过时的焦点任务，不能跳到旧记录。

## 8. 样式、主题与动效

继续使用 `rl-` 类名、作用域 tokens、显式样式导入和现有 Provider。不污染 `:root`、全局标签或宿主布局；Portal 继承主题、文案与减动。

工作台、阅读、展示共享基础语言，但允许不同内容宽度、密度与装饰强度。新 token 先解释语义和复用场景，避免给每个组件增加孤立的像素变量。

交互反馈可中断；状态事实先变化、动画后呈现。隐藏页面停止展示性循环；不通过延长动画掩盖异步状态。图标遵守基础层加定制层的既定策略，不恢复无规划混用。

## 9. 引擎与第三方接入

采用成熟机制，但 WzUI 拥有视觉和交互合同。选型 ADR 至少比较：实际需求、API 边界、维护状态、许可证、主题与键盘适配、SSR、Worker、包体与替代成本。

只有主题样式时优先直接提供主题和 recipe；需要跨调用者稳定的交互时才封装。不得包装一个完全透明且只能转发所有参数的“万能配置对象”，也不得隐藏宿主需要处理的安全边界。

重依赖不进入基础包。懒加载只解决执行时机，不自动证明包体隔离；必须验证普通页面的构建产物和依赖树。

## 10. 内容安全与资源生命周期

未来内容渲染默认不执行脚本；链接协议、内嵌 HTML、远程图片和下载行为有明确策略。原始文件路径不等于已授权 URL，组件不自行读取本地文件或上传用户资料。

对象 URL、观察器、事件监听、Worker、定时器和异步结果必须有创建与释放边界。测试卸载、快速切换、取消和重试；异步旧结果不能覆盖新详情。失败时提供可解释的 fallback，不伪装成空内容。

## 11. 公开 API、SSR 与迁移

Props 区分视觉 variant、事实 status、能力 capability 和动作 callback。展示分类允许扩展时提供 unknown fallback；控制状态机不因为分类开放而接受任意字符串。

依赖浏览器 API 的行为在客户端建立；服务端首屏不读取窗口、系统存储或随机 ID。SSR 首屏与客户端初始模式一致，再执行容器布局调整；记录无 JS 可读范围。

发布入口不含 CSS 副作用，样式显式导入。新增包须验证 types、dist exports、打包文件、独立安装、tree-shaking 和 SSR。未验证的导入路径不能先写进推荐示例。

提取已发布组件时保留兼容导出或提供迁移说明；0.x 不等于可以静默破坏调用者。版本推进与 API 变更的规则见 [质量与发布](quality-and-release.md)。

## 12. 架构退出条件

进入组件实现前，P030-00 必须留下包边界决策、状态表、布局／键盘／焦点合同、公开 API 草案、非目标、包体基线方案和对应测试计划。文档确认不代表组件已经实现。

出现新的底座、运行时、数据模型或重依赖时，暂停该子任务完成架构评估，其他不依赖它的主线任务继续。未通过实验的方向可以放弃，不影响已交付能力。
