# ROADMAP · WzUI 版本与后续路线

> 更新：2026-10-15；发布基线 0.2.0；0.3.0 库侧已实现，待授权发布。新路线以维护者个人长期 React 开发为中心，自主推进，消费项目通过需求反馈进入版本规划。

## 当前入口

完整路线见 [后续开发总路线](roadmap/README.md)，任务见 [执行清单](roadmap/execution-backlog.md)，首版细节见 [0.3.0 计划](roadmap/0.3.0-plan.md)。这三份是当前开发顺序与范围的权威入口。

当前已发布能力继续以源码、公开 API 和实际验收为准。规划中的组件、包和能力均未因文档合并自动变成已支持。

## 当前基线

0.2.0 已完成既定版本开发与发布。现有六包为 tokens、react、patterns、effects、agent-core、agent（patterns 为 0.3.0 新增，尚未发布）；基础原语、复杂交互、工作台、数据呈现、领域 UI、样式与发布工程作为后续起点。

本路线不重新验收该版本，也不把历史记录中的外部环境未执行项改写成通过。后续验证按每个版本的声明范围和实际证据执行。

## 0.3.0 最小完整闭环

基于已有 Workbench、DataTable、表单与覆盖层，新增页面与集合模式；不重造应用外壳和查询引擎。

目标操作为搜索、筛选、切换列表／网格、选择、批量操作、打开详情、章节定位和返回。候选公共组件有九项，P030-00 确认组件与 recipe 边界；通过 archive-desk 的两种数据形态独立验收。

版本门禁只要求 WzUI 能掌控的实现、参考应用、目标环境和真实产物证据，不等待其他应用全部安装。没有新增反馈时按 P030 任务继续推进。

## 需求、维护与发布

消费项目发现缺陷或组件需求时，提交 [需求记录](planning/templates/component-demand.md)，按 [反馈流程](roadmap/demand-workflow.md) 评估、分类、确定最小范围，再进入维护修复、当前版本或后续候选。

请求被接受不等于立即插入版本；版本冻结后变更必须记录取舍。库侧验收、真实发布、消费方验证分别追踪。维护修复不与新能力扩展混成无限范围。

每个工作包在 `.worktree/` 下施工、中文小步提交，全部完成后一个 PR；未经授权不触发 Actions、不合并、不发布。规则见 [质量与发布](roadmap/quality-and-release.md)。
