# CONTRIBUTING · 开发协作与提交规范

## 工作方式
1. 修改前先读 `AGENTS.md`、`DESIGN.md`、本次涉及的规范与 ROADMAP。
2. 每个任务先确定一个可验收的范围与关联里程碑；只在必要时增加新依赖。
3. 小步提交，每个可运行/可审阅的阶段提交一次。Commit message 使用中文，推荐 `类型：简述`，如「组件：增加基础按钮与状态测试」。
4. 不要直接复制设计概念图中的任意文本/数字/色码到代码；一切须回到 STYLE Tokens 核对。
5. 优先改基础抽象和复用组件，不为某张图片作逐像素的不可维护 hack。
6. 每次行为变更要同步文档、示例和测试；每次视觉变更需要响应式截图/可访问性复核。
7. 需要改已有 API、Token 名称、技术选型时写 ADR（docs/development/adr/NNNN-name.md）。

## 分支与 PR
- 首次空仓库初始化允许直推 main。后续开发使用 `feat/*`, `fix/*`, `docs/*`；禁止 force push main。
- PR 写清「目的、范围、实施、截图、测试、风险、回滚」；变更多时拆为功能主题提交。
- 用户没有要求启动自动 CI；除非另行明确批准，不加入 push 自动触发 workflows。
- 每个里程碑完成需记录验收结果和有意延期事项，不能仅凭「已写代码」关闭。

## 工具命令（初始化后）
```bash
corepack enable
pnpm install
pnpm dev
pnpm typecheck
pnpm build
```
若无联网环境、依赖未安装或命令失败，不得标记为通过。

## 安全与许可
不要上传真实 API key、证书和用户数据。每个第三方字体、图标、图像和代码依赖都留许可与来源，未核实前不打包发布。
