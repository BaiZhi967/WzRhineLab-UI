## 研究样张修复

问题来自固定 SVG viewBox 与独立 CSS Grid 宽度／gap。会话样张已改为实际 border box 底边中点与同尺寸 SVG viewBox，ResizeObserver 响应尺寸和显示变化，不写死 100/300/500 端点。

浏览器使用 SVG getScreenCTM 将路径点映射至屏幕，与卡片真实 bottom-center 比较：320、390、768、1280、1920 五宽度，每个宽度的三个点 dx=0、dy=0 CSS px。此证据仅针对研究样张；下述正式组件另外验收。

## 失败与修复记录

1. 公共入口测试最初无法解析尚未实现的 CalibrationReticle，0 tests collected；实现后通过。
2. 运行中切换系统reduce失败；核对motion14源码确实只保存mount时快照，统一修复到react内部共享订阅。专项单测首次未包MotionConfig=user，上游默认never使测试不成立；修正测试到真实Provider语义后通过。
3. progress反向单测在并行高负载下固定80ms采样晚于原采样值，改为捕捉反向实际起点并等待单调变化／最终目标，未删除中断与过期回调断言。
4. 首次多套浏览器并发运行时出现 Firefox 超时；串行隔离后通过，未据此断定唯一根因。4190 端口曾出现 same-URL navigation interrupted，改回已验证可用 4189 后 17/17 通过；没有变更产品导航掩盖环境问题。
5. 包门禁发现新useRhineMotion只导入内部hook时不满足既有client模块检测；用React useMemo稳定resolver对象，保留client边界并减少无谓函数变化，重跑通过。
6. effects全量超出原5KB预算，原因是新增3效果和可复用底座；按实测仅调整effects预算与新增4条独立入口，不提升无关包预算。
