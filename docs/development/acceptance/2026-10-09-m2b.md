## 3. 发现并修复的问题
1. **Toast 视口落在主题作用域外**：`RhineProvider` 首次渲染时，弹层挂载点的 ref 还是 `null`，Base UI 因此回退挂到 `<body>`。修复：挂载点改为 state（callback ref），节点就绪后再渲染视口。Dialog、Select 等所有弹层都受益于这一修复。
2. **通知关闭按钮默认 `aria-hidden`**：Base UI 在堆叠收起且焦点不在其中时，对辅助技术隐藏关闭按钮；聚焦进入后才暴露名称。测试改为验证这一行为，组件不做覆盖。
3. **菜单内容被截断**：菜单最大高度复用了下拉列表的 320px，7 项菜单需要滚动，axe 报滚动区域不可聚焦。修复：菜单只按可用视口高度限制。
4. **打开浮层时整页滚动到底部（视觉审查发现）**：Base UI 用 `absolute` 定位浮层，而挂载点在文档末尾，焦点移入浮层时浏览器把页面滚到末尾。修复：Popover、Menu、Select、Tooltip 的定位改为 `positionMethod="fixed"`。新增 E2E 断言：打开前后 `scrollY` 不变，且浮层在视口内并紧邻触发器。此问题在 M2-A 的 Select 上同样存在潜在风险，本次一并修复。
5. **media query 中的字面 px**：包边界测试拦下了 Toast 视口的 `479px` 断点。改为用 `clamp()` / `min()` 实现流式布局，不再需要断点。

## 4. 视觉审查
- 首轮：Popover 打开状态的两张截图里没有出现浮层，根因是第 3 节第 4 条的滚动问题。修复后复审，浮层出现在触发器下方，两张都通过。
- 首轮：390px 下对比表格看起来被裁切。表格本来就设计为横向滚动，修复方式是增加随滚动变化的边缘阴影作为滚动提示。
