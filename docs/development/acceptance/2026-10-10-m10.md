| 门禁 | 状态 | 证据 |
| --- | --- | --- |

| reduced motion 按属性类型降级 | ✅ | `resolveMotion` 单测（颜色 / 透明度 ≤120ms 淡入，位移 / 布局 instant，循环无 repeat，慢放不拉长减动回退）；E2E：Reduced 通道 Presence 无位移、Group 无错峰无位移、身份连续无中间帧；`reduced-motion.spec` 全部 24 个路由加载后、以及 Motion / Effects 两页播放全部演示后，没有无限循环、没有位移类动画、淡入不超过 120ms |

### 首轮失败与修复（按时间）
| 发现 | 性质 | 处理 |
| --- | --- | --- |
| Motion 页 Default 栏、MotionPlayer 的非 Reduced 通道用 `MotionConfig reducedMotion="user"`，在 Showcase「减少」下仍有位移 | **缺陷**（effects 与文档站） | 只有 Reduced 通道强制减动，其他通道继承外层偏好；effects 新增单测，反向验证会失败 |
| Slow ×0.25 通道把减动淡入拉长到 480ms（`reduced-motion.spec`「after playing · motion」发现） | **缺陷**（`resolveMotion`） | 减动回退不再按 speed 缩放；单测新增断言 |
| roadmap 列出 `showcase` 预设但 `transition` 中没有 | 缺口 | 补齐，并用测试锁定 token ↔ 预设一一对应 |
| Toast 中途关闭按帧计数的断言在 Firefox / WebKit 并行负载下不稳定（约 30fps，ease-out 一帧走完大部分距离） | 测试问题 | 改为读取 `data-ending-style` 上的 transform 过渡本身（CSSTransition），并保留单调性与「不先回到原位」的断言 |
| Group 错峰、Tabs 改道、Reveal 隐藏在 WebKit 16 并发下不稳定 | 测试问题 | 错峰改为读取每项 WAAPI 动画的 `delay`（0/24/48/72/96/120/120）；Tabs、Toast 的前置条件（必须落在动画中途）不满足时重试；Reveal 的点击与隐藏放在同一次页面任务内 |

## 4. 反向验证
逐项破坏实现、确认测试失败、再恢复（脚本化，恢复后 `git status` 干净）。前四项是同一批破坏，各自拦住的测试互不重叠；错峰上限另外单独破坏过一次，确认 group 测试只因它失败：

| 破坏 | 拦住的测试 |
| --- | --- |
| Tabs 指示器 `transition: none` | E2E Tabs retarget |
| 错峰上限 ×10 | E2E group（排期变为 …144，而不是 120） |
| Presence 减动时仍保留位移 | E2E presence、group |
| `usePageVisible` 永远返回可见 | E2E Orbit / Reveal / Scan 隐藏页三项 |
| 去掉 ArchiveCard 的 `layoutId` | E2E 身份连续（默认通道没有中间帧） |
| Dialog 去掉 `AnimatePresence` | E2E Dialog 中断（重新打开前弹层已不存在） |
| Toast `transform` 过渡改为 0ms | E2E Toast 中途关闭 |
| Orbit 暂停时回到 0° | E2E Orbit（隐藏后角度小于隐藏前） |
| MotionPlayer 的 Reduced 通道不再强制减动 | E2E 身份连续、group、presence |
| `RhineProvider` 的 MotionConfig 固定为 `user` | E2E「page-level reduced motion」、reduced-motion「after playing · motion」 |
| `data.css` 中 Stat 骨架的减动规则不再 `animation: none` | reduced-motion · data（同一规则组内 3 个无限循环被列出） |
| reduced-motion 扫描改用 `motion: 'user'`（检查规则本身） | reduced-motion · data |
| MotionPlayer 通道恢复为 `reducedMotion="user"` | effects 单测「a surrounding reduced-motion preference is kept」 |
| 减动回退按 speed 缩放 | react 单测「speed scales durations for review lanes only」 |
| `transition.showcase` 改名 | package-boundary「motion presets derive from the shared duration tokens」 |

没有拦住的一项：把 ArchiveCard 的 layout 过渡改成固定 420ms（不经 `resolve`），E2E 仍通过。原因是 motion/react 在 `reducedMotion="always"` 下自己会关闭 layout 动画，这是第二层保护，行为上没有缺口；单测 `resolveMotion('layout', …)` 覆盖解析本身。

## 6. 偏离、未覆盖与遗留
- **没有单独的 `RhineMotionProvider`**：沿用 `RhineProvider motion` + `MotionConfig`（ADR-0007「留给 M11」）。
- **基础组件尚未逐个改用 `resolve`**：Dialog 仍用 `get()`，减动时透明度也是 instant（比 ADR §3 允许的更保守）。Dialog.tsx 属 M9 冻结文件，未改动，交给协调者决定。
- **低帧率**只在 Chromium 下对 Dialog 做了 CPU 降速抽查；真机、30fps 设备与其他组件未测。
- 中断与错峰在负载下的部分断言读取浏览器的动画对象（CSSTransition、WAAPI 的 `delay`），不只看像素位置；像素级断言仍保留单调性与「从当前位置接续」。
- WebKit 16 并发下 3 项既有 spec 失败（第 3 节），M10 没有改动相关文件，未修复。interaction「loading keeps focus」的原因已定位（模拟任务 1600ms 在负载下先完成）。曾尝试在 e7d1e87 上对比，但临时 worktree 的依赖链接实际解析到了 M10 的包，**结论无效**，不作为证据。
- **过程事故**：清理上述临时 worktree 时，`git worktree remove --force` 跟随了指向 M10 worktree 的 node_modules 目录链接，删除了 M10 worktree 的已跟踪文件和依赖。当时所有改动都已提交，已用 `git restore --source=HEAD` 恢复、`pnpm install --frozen-lockfile --force` 重装，`git status` 干净；之后重新跑了 typecheck、全部单测和三内核 E2E（第 3 节数字均为恢复后的结果）。主仓库未受影响。
- 读屏软件、200% 缩放、真机触控仍未人工验收；没有人工键盘验收记录。
- API 参考（`docs/api/react.md`）同时包含 M9 脚手架组件的导出，合并 M9 后需重新生成。
- 视觉基线只覆盖 Chromium on Windows。
