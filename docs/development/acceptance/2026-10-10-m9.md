## 3. 反向验证（临时改坏实现 → 测试失败 → 恢复）
| 改动 | 结果 |
| --- | --- |
| AlertDialog 初始焦点改为确认按钮 / 去掉 | 单测失败；E2E 3 项失败（含 archive.spec 两项） |
| 等待确认时不拦截关闭 | 单测、E2E「busy confirm」失败 |
| 去掉过期 Promise 防护 / reject 后不聚焦确认 / 错误提示去掉 `role="alert"` / 重开不清错误 | 各自单测失败 |
| `onCloseRequest` 返回 false 不取消 / 原因映射错 | 单测与 E2E 失败 |
| 减动时仍上移 8px | E2E 逐帧采样读到 `translateY(8px)` |
| Drawer 窄屏判断恒为 false / `side` 写死 / 忽略 RTL / 不传 portal container / 去掉 Provider 减动规则 | 各自单测失败 |
| Drawer 去掉进出场过渡（`transition: none`） | E2E「exit completes before unmount」失败（首版断言未能发现，已改写后复验） |
| Alert polite 不出角色、assertive 变 status、角色放到根节点；Callout 去 note；EmptyState 忽略 headingLevel；Skeleton 去 aria-hidden；Spinner 有 label 不出角色、不响应减动 | 各自单测失败 |
| Toast 去掉 id、操作不关闭、忽略 keepOpen、无 10 秒下限、promise 失败默认值丢失 | 各自单测失败；E2E 撤销与去重失败 |
| 去掉 OS 减动下的骨架规则 | package-boundary 失败 |

已知弱点：只删掉 Drawer 中 `eventDetails.cancel()` 一行时测试仍通过（组件受控，不调用 `setOpen` 就不会关闭；`cancel()` 只是阻止 Base UI 继续派发），这一行目前没有可区分的测试。

## 5. 偏差与决定（已写入 ADR-0006）
- AlertDialog 的 `errorText` 渲染在正文末尾；嵌套 AlertDialog 需放在 Dialog 内部。
- Drawer 增加 `initialFocus` / `finalFocus`、`DrawerClose`，关闭原因多一个 `swipe`；未接入 `VirtualKeyboardProvider`；档案检索在页面单列（< 1024px）时就改用 Drawer。
- Alert 的 live 角色放在消息文字容器上。
- Toast：带操作通知的超时下限要读 Provider 默认值，`ToastProvider` 改为包装组件（属性不变）；promise 的字符串阶段作为标题。
- **行为变化**：Toast 操作点击后默认关闭（CHANGELOG 已注明迁移方式）。

## 6. 未覆盖
- 人工键盘、读屏软件（NVDA / VoiceOver）、200% 缩放与真机验收。
- Drawer 滑动关闭没有手势 E2E，只在类型与原因映射层面覆盖；需要真机验证。
- 底部弹出内含输入框时的软键盘行为（未接入 `VirtualKeyboardProvider`）。
- 视觉基线只在 Windows Chromium 上建立。
- AlertDialog 危险按钮 hover / pressed 色由 `color-mix` 计算，没有对应的对比度 manifest 条目（默认态有，axe 明暗通过）。
